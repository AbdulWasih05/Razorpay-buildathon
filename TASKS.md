The schema **refuses** an agentic capture missing its mandate, agent identity, trace or orchestration log — that absence is the exact failure the product exists to prevent, so it is rejected at the door rather than discovered useless at dispute time. Generators for: merchants, customers, Reserve Pay mandates (consent timestamp, limit, validity window, per-merchant), agent conversation traces (intent → selection → confirmation turns), orchestration audit logs (timestamped agent actions incl. payment call referencing real test-mode `pay_` ids), orders + fulfillment records — all emitting evidence packs through P1.0's endpoint. **Determinism design (round-4 fix):** the capture API accepts client-supplied seed-derived external ids and `occurred_at` timestamps; server-generated row ids and `created_at` are excluded from comparison. Store holds 100 packs / 44 mandates / 220 turns / 269 orchestration entries / 100 payments. Determinism, prompt-input and canonical-serialisation tests green.
  - *What to understand here:* determinism rests on three choices — no `Math.random()` (a ~10-line mulberry32 seeded from a string), no `Date.now()` (every timestamp is an offset from a hard-coded 2026-06-01 epoch), and **positionally independent streams** (each case derives its own generator from `seed+class+index`, so editing scenario a1 changes a1 instead of silently shifting the whole corpus).
